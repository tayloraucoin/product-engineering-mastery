# STK-6 C5 — no flash of the wrong theme on a hard reload in dark mode

Verified 2026-10-03 by the build agent (Claude Opus 5.5) in the Claude desktop app's browser pane, against `yarn web:dev` (Next.js 16.3.8, next-themes 0.4.6) at the commit this record names.

## What a flash would need, and why it cannot happen

1. **The colours read only the class.** `packages/config/tailwind/preset.css` sets the dark semantic names under `.dark`; there is no `prefers-color-scheme` block left, so nothing in the CSS can pick a theme on its own.
2. **The class is set before any content is parsed.** In the server-rendered HTML of `/`, the first element of `<body>` is next-themes' inline script, called as `("class","theme","system",null,["light","dark"],null,true,true)`. It reads `localStorage.theme` (falling back to `system`, resolved with `matchMedia`) and adds `light` or `dark` to `<html>` synchronously. The `<header>` (toggle) and `<main>` come after it. The one stylesheet is in `<head>`, so it is render-blocking: no content paints before the script has run.
3. **React does not undo it.** `<html suppressHydrationWarning>` in both root layouts; the console after each reload held only the React DevTools notice and `[HMR] connected`, with no hydration or script-tag error.

## Observed

| Stored theme | Pane's `prefers-color-scheme` | After a reload: `<html>` class | Body background |
| ------------ | ----------------------------- | ------------------------------ | --------------- |
| `dark`       | dark                          | `dark`, `color-scheme: dark`   | `lab(2.75 0 0)` |
| `dark`       | light (emulated)              | `dark`                         | `lab(2.75 0 0)` |

The second row is the case a flash would show in: the system says light, the person chose dark, and the page came up dark with no light frame captured in the screenshot taken after load.

## Limit

A still image and post-load DOM reads cannot show a single painted frame. This record proves the mechanism (class-only CSS, a synchronous script ahead of all content, a render-blocking stylesheet) and the outcome after reload. A person watching a hard reload with the network throttled is the stronger check; it was not done in this thread.
