# C5: removal rehearsal of remove-api.md on a scratch copy

**Deferred to a person** (the contract's reason: a removal rehearsal on a copy is done by a person). The agent's own rehearsal, below, is supporting evidence, not the verdict: on its copy, `yarn verify` was not wholly green, because of two failures from STK-9 and STK-16 that were there before the removal.

## For the operator

Once STK-9 and STK-16 are closed and `yarn verify` is green on the shared branch:

1. Copy the repo somewhere disposable (`git archive HEAD | tar -x -C <copy>`), then run `git init` and `yarn install` in the copy.
2. Follow `docs/runbooks/remove-api.md` from top to bottom.
3. You should see:
   - `git grep -il trpc -- apps packages tooling` prints nothing;
   - `yarn check-stack` prints "nothing missing, nothing left behind";
   - `yarn verify` exits 0.

## The agent's rehearsal (supporting evidence)

Done by the building agent on 2026-10-04, on a copy of HEAD `41b60f5` (`git archive` into the session scratchpad, `yarn install`), never the shared checkout. The same copy was checked before the removal, so a failure that was already there is not counted against the runbook.

Every section of `docs/runbooks/remove-api.md`, top to bottom:

1. **Files to delete:** `packages/api/`, `apps/web/app/api/trpc/`, `apps/web/lib/trpc/`.

3. **Boundaries entries:** the element, the matrix row, `FORBIDDEN_EDGES`, the `@trpc/*` owner, `@trpc/*` out of `TRANSPORTS`, the probes that name `@trpc` or `@pem/api`.
4. **Verify:** `"removed": true` on `stack.api`, `yarn install`, `yarn check-stack`, the grep, check-refs into `refs-pending.json`, then `yarn verify` and each of its steps.
