# Brief — Migrating an existing codebase into the practice

> Framed in the Usher thread of 2026-10-06 from the builder's settled answers, the operator's answers to interview rounds 1 and 2, three read-only repo reads (synapse, conscious-connections, taylor-aucoin, all 2026-10-06) and [`research/brownfield-adoption.md`](research/brownfield-adoption.md). Crucible's pre-mortem is folded into "Risks". Labels: verified (read in a file, path cited), secondary, judgment. Sibling: the new-project track, which assumes a fresh duplicate; this epic is for a repo that already exists and keeps its history.

## Job

- **Trigger:** "This codebase already works and has a team on it. I want it under the practice by tomorrow: the agent spine, the workflows, the specs as living truth, a verify command, the reviewer map. The stack can follow later, part by part. Nothing stops and nothing is thrown away."
- **Baseline:** today a repo is brought under the conventions by hand, and each repo copies the previous one. Synapse's conventions were hand-copied from Conscious Connections and still carry its references (verified: `~/lighthouse/synapse/AGENTS.md`, "copied from Conscious Connections and never imported"; `docs/architecture/codebase-conventions.md` there still names a `mobile-relationships` app). What goes wrong: fixes strand in whichever repo made them; every repo has a different spine (synapse: a 182-line `AGENTS.md`, nested `AGENTS.md` in three workspaces, a tracked `.claude/settings.json` with permissions and no hooks, no `.claude/rules`, no skills, no subagents; verified); none has a single verify command (synapse CI chains `lint`, `lint:boundaries`, `check-types`, `build`; verified: `.github/workflows/ci.yml`); records live in formats of their own (synapse: 861 `DEVIATIONS.md` lines and 111 `TECHNICAL-DECISIONS.md` entries across nine track folders under `docs/specs/`; verified by count); and nothing tells an agent what the repo already has or how far it sits from the conventions. The only written path in is new-project, whose strip and rename steps delete the repo's own history and cannot be run on a repo we mean to keep. One piece of prior art exists and is not yet a path: `toolkit.json` already admits the tiers `overlay` and `overlay-local` beside `starter`, and two scripts skip the host repo's docs under them (verified: `tooling/lib/toolkit.ts`, `tooling/lint-frontmatter.ts`, `tooling/directory-map.ts`); nothing else in the tooling knows the tier, and no decision record describes it (not found).

## User

- Taylor, as the operator: a fractional engineer entering a company's existing repo, or bringing one of his own three (synapse, conscious-connections, taylor-aucoin) in, directing a coding agent in Claude Code for one working day, while a team may keep committing to the default branch. State of mind: wants the way of working live tonight and is willing to leave the stack for later. Constraint: a live product means every hosted step stops for a person. Later, anyone porting the practice into their own repo walks the same path.

## Metric

- **Signal:** a qualitative bar with a clock. A cold Claude Code session, given only the procedure and a committed target repo, finishes layer 1 in one working day: the spine loads as `docs/runbooks/onboard-agent.md` checks, `toolkit.json` describes the repo, a verify command runs the repo's own checks and is wired into its CI where one exists, the living truth and the records are mapped in (moved and indexed, not rewritten), and everything that did not cross over is a named gap with a plan. Inside the epic the bar is the desk walks: synapse (near), conscious-connections (middle) and taylor-aucoin (far, walked by Crucible as the runbook's reviewer).
- **By when:** the operator's synapse run after the epic closes is a dry run: its stops are fixed in the runbook, as new-project's were. The clock is timed on the second repo, conscious-connections (operator, 2026-10-06; priority synapse, then conscious-connections). [ASSUMPTION: the synapse run happens within two weeks of the epic closing; the operator sets the date.]
- **Kill criterion:** a run takes more than two working days to finish layer 1, or needs more hand repair than writing the repo's `AGENTS.md` and `toolkit.json` by hand would have. Then the procedure is wrong, not the repo. Merge-side (operator, 2026-10-06): after the migration branch merges, the team's next week of commits passes with no revert of the spine, the hooks or the settings.

- **The research** (`research/brownfield-adoption.md`, 2026-10-06). No source shows a full brownfield adoption in one day; the durations found are months (strangler fig) and weeks (Airbnb's 3.5K-file migration). What is documented and does not block product work: freeze existing debt as a committed baseline (ESLint bulk suppressions since 9.24.0, ratchet files) so a rule is enforced for new code only; one verify entry point over the repo's own commands; a short instruction file that points at existing docs (OpenAI: about 100 lines as a map; Anthropic: under 200); hard rules in hooks or CI, never prose, because every vendor calls instruction files advisory. Baseline files cause merge conflicts unless they are one line per file and rule (Notion). The day-one versus later sequencing is the research author's judgment, not a measured result.
- **The precedent** (verified): new-project's dry runs on a fresh duplicate took 61 minutes with 21 stops, then 44 minutes with 11 stops (`docs/runbooks/new-project/README.md`, status line). A foreign repo has more unknowns than a duplicate, so a first real run will have more stops; the day-one bar is for the rehearsed procedure, not the first attempt (judgment).
- **Counter-evidence.** Two studies found repository context files do not reliably improve agent task success and raise cost by over 20 percent (arXiv 2602.11988, Feb 2026; arXiv 2607.27250, Jul 2026, both cited in the research file). If true, layer 1's value rests on the workflows, the specs and the deterministic checks, not on the `AGENTS.md`, and the procedure must not spend its day polishing prose. Second: a procedure nobody has run cold is presumed broken (Usher, belief 6); this epic ships desk walks, and the first cold run happens after it closes, so the epic cannot prove its own clock.

## Settled before this brief (from the builder; not re-asked)

1. This epic builds the procedure in this repo only. It never runs it against synapse or writes there. The operator runs it on synapse after the epic closes.
2. Day one moves the way the codebase works, all at once: the agent spine, workflows, roles, specs and living truth, `toolkit.json`, a verify command mapped to the repo's own checks, the reviewer map. Tech that cannot cross over becomes named gaps with a plan and never blocks day one.
3. Adoption is layered: (1) the way of working, (2) the checks, (3) code conventions and stack, part by part. A repo may stop after any layer. The procedure covers a full migration through every layer.
4. Built for any repo, proven on one: an assessment scores the repo's distance from the conventions, and the distance picks the path.
5. Existing records are mapped in, one decision per kind of document (UX spec to living truth, decisions to records, guides to the design layer or path rules, closed specs archived as they are). Nothing is deleted; each mapping is the operator's call.
6. Preconditions: the target is committed and pushed before the run, and the procedure checks for it. Live and not-yet-deployed repos are both handled: database steps rehearsed locally, every hosted step stops for the operator.
7. Tooling wherever a step is mechanical and repeated. [ASSUMPTION: at least a read-only assess command that prints the distance report the interview starts from.] The Technical stage decides the set, as a recommendation the operator confirms.

## Settled in this thread (rounds 1 and 2, 2026-10-06)

- **Branches in the target.** Precondition check: clean tree, committed and pushed, not on the protected branch. One migration branch the operator creates and names before the run, the repo's own convention winning over `agent/{id}`; one commit per step; never a push, a merge or a touch of the protected branch. `toolkit.json`'s `branchPattern` and `protectedBranch` are read from what the repo already does. The operator merges.
- **A live team.** Other developers keep committing to the default branch during the run. Baseline files are one line per file and rule so they rebase; any step that rewrites many files (a scope rename) is flagged as a conflict risk and goes last or is left as a gap.
- **The far case.** Not a hypothetical: the procedure is desk-walked against the operator's three repos, synapse, conscious-connections and taylor-aucoin, and all three are expected to migrate smoothly. The read shows taylor-aucoin is a true far case (single app, no workspaces, no CI, no tests), so the far desk walk is on a real repo. The runbook's Q2 reviewer, Crucible, walks it as that far repo.
- **In scope by the operator's choice:** wiring the mapped verify command into the target's existing CI.

## Out of scope

- A big-bang rewrite path; deleting or rewriting the target's history (settled).
- Automated code rewriting: codemods or agent-driven bulk transformation of the target's source to reach layer 3. Each gap gets a plan; the moves are later tickets in the product repo.
- Non-JS stacks past layer 1: a Python, Go or Rails repo gets layer 1; layers 2 and 3 become one named gap each.
- Harness files for Cursor, Codex or Copilot beyond `AGENTS.md`, which those tools read. The Claude Code harness is the one installed.
- Running or rehearsing the procedure on any of the three repos inside this epic.

## Risks

Crucible's pre-mortem, run 2026-10-06 against this draft, two scenarios (taylor-aucoin as the far repo; the one-day promise failing on synapse). Verdict: survives with changes. Each cited path was re-read in this thread. The layer model, verify over the repo's own commands and one-line-per-file baselines survived untouched.

1. **Fatal if true: the tooling assumes the starter's layout.** `yarn verify:fast` runs Turbo over affected workspaces (verified: `tooling/verify-fast.ts`), and the stop hook calls it at every stop (verified: `tooling/hooks/stop-gate.ts`). Only `lint:docs` and `directory-map` honour the existing overlay tier (verified: `tooling/lint-frontmatter.ts`, `tooling/directory-map.ts`; the tiers `starter`, `overlay`, `overlay-local` are in `tooling/lib/toolkit.ts`). On taylor-aucoin, with no `turbo.json` and no workspaces, every stop blocks, and the afternoon goes to porting tooling or the hooks are removed. Likelihood: near certain on taylor-aucoin, low on synapse. Retired by: the Technical stage audits every script and hook for layout assumptions and extends the overlay tier to all of them, proven in this repo against a single-app fixture (`tooling/lib/scratch-repo.ts` exists for fixtures).
2. **Fatal if true: layer 1 imposes the toolkit's team policy on merge.** Settings and hooks are tracked, so a merge hands them to the whole team. The Bash guard blocks any push, any commit on `main` and any commit message without a work-id (verified: `tooling/hooks/bash-guard.ts`). Synapse's and conscious-connections' `AGENTS.md` say no branches and no PRs during slice work. The morning after the merge, every teammate's agent refuses the team's own workflow, and the team reverts. The kill criterion times only the operator's run and never sees this. Likelihood: likely wherever a team exists. Retired by: the assess report lists every conflict between the target's instruction files and settings and the toolkit's; the interview rules on each before the spine is written; the target's settings and hooks are derived from those rulings, not copied. Adopted as the merge-side kill criterion (Metric).
3. **Serious: the stale protected branch.** The tooling's base ref is `toolkit.json`'s `protectedBranch` (verified: `findBaseRef` in `tooling/lib/git.ts`). Read from the repo, that is `main`, 92 commits behind synapse's work, so the fast verify and `check-specs` treat 92 commits of old code as the migration's diff. Retired by: the precondition check fails when `protectedBranch` does not contain the run's base, and the interview sets it to the branch work actually merges into.
4. **Serious: "mapped in" is undefined.** Synapse's four UX spec versions and 861 deviation lines are one job: the deviations are where the code differs from the spec, and the code has moved since. Making `specs/web/ux/` true is the UX-spec work new-project hands to its own thread on the deepest model. Either the day goes there or the living truth is written shallow and the first ticket builds on false truth. Retired by: day-one mapping is move-and-index, each body kept byte for byte (as `.claude/rules/docs.md` rules for filed outputs); promotion to living truth is a named gap with a plan; the synapse desk walk times this step on its own.
5. **Serious: the budget displaces the repo's own guidance.** `tooling/budget.ts` caps `AGENTS.md` at 100 lines and `CLAUDE.md` at 20 (verified). Taylor-aucoin's 80-line human-written `CLAUDE.md` and synapse's 182-line `AGENTS.md` are the one kind of context file with empirical support (research, section 4), and the cap cuts them. Retired by: existing human-written lines move verbatim into path rules or a nested file, the toolkit's lines are trimmed first, and the agent-readability test in `docs/runbooks/onboard-agent.md` §5 runs with a brief that needs a fact found only in the old file.
6. **Serious: the reviewer map cannot see SDKs used everywhere.** Reviewer globs match paths only (verified: `tooling/lib/toolkit.ts`). Taylor-aucoin imports Stripe and Supabase across the app, so a Stripe call in an ordinary component matches no `**/billing/**` glob and a Q3 change ships at Q1. Retired by: the assess report lists every file importing a money, auth or AI SDK, and a check fails when a reviewer glob matches zero files in the target.
7. **Friction: no CI to wire into.** Taylor-aucoin has none. The Signal now reads "wired into its CI where one exists"; otherwise CI is a named gap or a hosted step the operator takes.
8. **Friction: new dependencies in a live repo.** The tooling imports `yaml`, so `package.json` and `yarn.lock` change during the day while the team commits. Retired by: those changes land in the run's first commit so a rebase meets them early.
9. **Friction: prior art not named.** The overlay tiers already exist in the tooling and were proposed in the engineering-layer report (`docs/research/engineering/engineering-layer-report.md`, "two adoption tiers"); no decision record documents them (not found in `docs/decisions/`). The Technical prompt cites them as the base so no second adoption mode is built beside them.
10. **Friction: the logic of the clock.** The brief holds the one-day bar to a rehearsed procedure, yet the first rehearsal is the timed synapse run. Base rate: new-project's desk walk found four things; its two dry runs stopped 32 times. Decided 2026-10-06: the synapse run is a dry run whose stops fix the runbook; the clock is timed on conscious-connections (Metric, By when).
