### Settings, derived (Risk 2)

Lorimer was consulted. The assess report lists each policy the toolkit enforces next to any target line that conflicts with it. The interview rules each policy **team** (`.claude/settings.json`, tracked) or **operator** (`.claude/settings.local.json`, gitignored, the overlay-local mechanism). The floor is never offered and is always tracked.

### The repo's own instruction lines (Risk 5)

The caps stay: `AGENTS.md` 100 lines, `CLAUDE.md` 20 (verified: `tooling/budget.ts`). Raising them under overlay was beaten (Lorimer, belief 2). Each human-written line of the old `AGENTS.md`, `CLAUDE.md` and nested files goes to exactly one place, verbatim:

1. **Global and still true:** `AGENTS.md` "House rules".
2. **About one folder:** that folder's nested `AGENTS.md`. Synapse already has three (verified).
3. **About a file type:** `.claude/rules/house-<topic>.md` with `paths:`.
4. **Overruled by a ruling:** not carried; the ruling is cited in the record.

Toolkit lines are cut first: any line a hook or check enforces, then the commands table, which is replaced by the target's. A global human line is never trimmed silently; the operator rules on it. The old files are kept byte for byte (T5). **Proof:** the `docs/runbooks/onboard-agent.md` §5 test, with a brief that needs a fact found only in the old file. Sample: TA's `CLAUDE.md` rule that the interface wins over the atmosphere (line 38, verified).

### A named gap with a plan, as a file

A gap is a **drafted ticket** under the target's migration epic: `specs/_shared/epics/<P>-migration/tickets/<P>-NNN-<slug>/contract.md`, made by `yarn contract:init`. Its Build notes hold:

- the layer
- what did not cross, and why
- the plan (the recipe path or the steps)
- the conflict-risk flag, and the trigger to start
- an estimate, labelled as one

Drafted tickets already show in `yarn status` (verified: the SessionStart line lists "Drafted"), so the burn-down needs no new format. **Beat:** a `gaps.md` table, which would be a second ledger that `yarn status` and `check-specs` cannot see.
