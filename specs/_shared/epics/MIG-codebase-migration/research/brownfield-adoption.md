# What are the proven patterns for bringing an existing, working codebase under a new set of engineering conventions and an AI-agent harness within about a day, without stopping product work, and then converging its stack over time?

## Answer
No source shows that a full brownfield adoption fits in one day. What the sources do support is a narrower set of day-one moves that do not block product work. Each is documented, and each separates "stop new violations" from "fix old ones": (a) freeze existing debt as a committed baseline instead of fixing it (ESLint bulk suppressions since v9.24.0, April 2025; Vercel Conformance allowlists; Notion's and qntm's ratchet files);\[1\]\[2\] (b) expose the repo's existing commands through one verify entry point the agent can run (Claude Code's best-practices doc calls a runnable pass/fail check the highest-leverage step; Turborepo recommends root scripts that call `turbo run <task>`);\[3\]\[4\] (c) add a short instruction file that points to existing docs instead of copying them (Claude Code: under 200 lines; Codex: 32 KiB default cap; Cursor: reference files instead of copying them; OpenAI's harness team, per Ryan Lopopolo on 11 Feb 2026: a roughly 100-line AGENTS.md used as "a map, not a 1,000-page instruction manual"). Hard rules go to deterministic hooks or CI rather than prose, because every vendor says instruction files are advisory.\[5\] Gradual convergence has decades of evidence behind it: strangler fig / legacy displacement (Fowler, rewritten August 2024), Larson's derisk–enable–finish migration playbook (2018), and codemod or LLM-assisted bulk migrations with per-file validation (Airbnb: nearly 3.5K test files in 6 weeks against a 1.5-year manual estimate). Remaining gaps are tracked in the same baseline files, used as burn-down ledgers. The weakest evidence concerns the agent layer. Two arXiv studies found that repository context files do not reliably improve task success: Gloaguen et al. (ETH Zurich, arXiv:2602.11988, February 2026) found they do not generally improve success while raising inference cost by over 20% on average, and Khatri (arXiv:2607.27250, July 2026) found that a real AGENTS.md never turned a near-miss into a pass on either agent tested; LLM-generated files did slightly worse than none. "Write a context file" therefore has empirical support only for a minimal, human-written file that states non-obvious requirements. Tool behaviour changes fast: Claude Code began reading AGENTS.md natively only at v2.1.277.\[5\] The day-one versus later sequencing in this note is judgment, not something a source measured.

## Promote to library
Yes, with an expiry. The pattern-level findings are durable and not tied to one epic: baseline-then-burn-down ratchets (qntm 2021, Notion, ESLint), derisk–enable–finish migrations (Larson 2018), strangler fig (Fowler 2024), deterministic enforcement over prose, and short pointer-style instruction files. The empirical result that context files help little is recent and worth keeping as a counterweight. The facts most likely to go stale are Claude Code's AGENTS.md handling and version gates (v2.1.277/v2.1.283/v2.1.285), hook event lists, Cursor's rule types and nested-AGENTS.md behaviour, Codex's 32 KiB cap, Copilot's path-instruction support matrix and VS Code nested-AGENTS.md default, and package-manager cooldown defaults. Re-verify by 6 Jan 2027 (quarterly), and immediately after any major release of these tools.
