# Postmortems

**What this is.** One blameless template, [`postmortem.template.md`](postmortem.template.md), filled to the depth the case calls for, and one working ledger, [`convention-log.md`](convention-log.md), where every finding that points at a convention waits for Taylor's decision. Every path runs the template's **Trace**: the tickets that touched the failing code, and what their criteria and review missed. A fix is filed as a ticket, never as an intention.

**Come here when.** Something reached a user that should not have, or was caught late enough that the work loop should have caught it sooner.

**Start with.** Find the case below, copy the template to `docs/postmortems/YYYY-MM-DD-<slug>.md`, and fill the sections it names.

| Case | Fill | Also | By |
| --- | --- | --- | --- |
| **Production incident:** users saw an outage, an error or wrong data | Every section except the AI fields | Timeline from detection to resolution, with what the monitors saw beside what was true | five working days after resolution |
| **A bad merge caught before release:** on the base branch, not yet shipped | Summary, Trace, Contributing causes, Lessons; Impact reads "none: caught before release" and says who caught it and how | The Trace carries this case: the work loop let it through, so name the criterion or review that should have stopped it | before the next release |
| **An agent that went wrong:** a destructive command, edits outside its planned paths, a rule ignored, a claim of done without evidence | Summary, Trace, Contributing causes, Lessons; Impact names what was lost or redone | Keep the session transcript beside the postmortem. Name what the agent was told (the always-on files, the path rule, the skill, the hook) and whether it loaded. A hook or `.claude/settings.json` change is Taylor's to make | five working days |
| **A wrong AI output shown to a user:** an unsupported claim, a wrong source, a harmful answer | Every section, the AI fields included; the claim by opaque ID, never its content | Add the failure to the surface's failure modes and an eval case for it ([`failure-modes.template.md`](../../measurement/evals/failure-modes.template.md)), so the next run of the evals would catch it | five working days |

**Where findings go.**

- A fix to the product is a ticket, linked from the template's Lessons table.
- A finding that suggests changing a convention (a rule in `AGENTS.md` or `.claude/rules/`, a check in `tooling/`, a reviewer glob or tier in `toolkit.json`, a template, a skill, the canon) is also one row in [`convention-log.md`](convention-log.md). The postmortem proposes; Taylor decides there, and an accepted row becomes an amendment with its ledger line.
