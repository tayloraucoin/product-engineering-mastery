# Evals templates

**What this is.** Three templates for an AI surface, filled in order: the surface and its pass bar, the catalogue of binary failure modes, then one judge per failure mode, validated against human labels before it gates anything.

**Come here when.** A product has, or is about to have, a feature that makes claims to users through a model.

**Start with.** [`surface.template.md`](surface.template.md). Nothing here is needed until a product has an AI surface.

## A worked scenario: checking an AI feature before release

Synthetic throughout: the product, traces and numbers are invented.

A records app adds **record summary**: a model reads a record's document and writes a short summary, each sentence citing the line it came from. Users will act on these summaries without opening the document, so a wrong one costs more than no summary. Nothing ships until the answers are checked.

1. **Say what it promises.** **Compass** names this as the surface that matters; **Tally** fills [`surface.template.md`](surface.template.md): "every sentence in the summary is supported by the line it cites", answer and source graded separately, a pass bar of 95 percent per judge on the test set. **Engineering** owns the harness that runs the cases.
2. **Read the traces before writing any judge.** **Tally** reads 120 summaries generated from seeded records, labelled synthetic, and fills [`failure-modes.template.md`](failure-modes.template.md) with what they actually show: FM-01 a claim the document does not support (14 of 120), FM-02 a citation pointing at the wrong line (9), FM-03 a date that differs from the source (6), FM-04 a refusal when the answer is there (3). **Assay** checks that each mode is a yes-or-no question someone could answer by looking.
3. **One judge per failure mode.** For each mode, **Assay** writes the judge's wording in [`judge.template.md`](judge.template.md), the **product owner** labels 40 passing and 40 failing examples for each of the dev and test sets, and **Tally** measures how often the judge agrees. FM-01's judge catches 93 percent of real failures and clears 90 percent of real passes on the test set, so it is trusted. FM-03's catches only 71 percent, so it does not gate; a plain code check that compares dates replaces it.
4. **The gate.** The release check runs every case through the trusted judges. FM-02 passes at 91 percent, under the 95 percent bar, so the release is blocked. A builder fixes how line numbers are carried into the prompt, the rerun passes at 97 percent, and Tally records the run, its date and commit in the surface card's Last run row.
5. **After release.** New traces are read on the same schedule as the readouts. A new failure becomes a new row and a new judge; a changed pass bar is written in the surface card's changelog, so nobody moves the goalpost quietly.
